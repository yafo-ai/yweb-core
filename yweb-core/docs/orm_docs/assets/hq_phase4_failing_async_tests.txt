## C. Phase 0 扫描报告中标记的唯一嫌疑点的实际结果

  位置: tests/test_scheduler/integration/test_history.py:392
        （TestSchedulerWithDatabaseHistory.test_job_execution_records_history
         —— @pytest.mark.asyncio async def，函数体直接
         `SchedulerJobHistory.query.filter(...).first()`）

  预期: HybridQueryProperty 接入后，async 上下文下 .first() 返回
        _HybridTerminal，`history is not None` 能过，但下一行
        `history.job_code` 访问终端对象的属性 → AttributeError

  实际: PASS（19/19 绿）

  根因: tests/test_scheduler/conftest.py:67 的
        `scheduler_db_session` fixture 在 setup 时直接执行：

            CoreModel.query = session_scope.query_property()

        这一行**硬覆盖** Model.query 为原生 SA query_property（没有
        包 HybridQueryProperty 也没有 AsyncSafeQueryProperty），
        绕过了 Phase 1/2/3/4 的所有 async 安全链路。

  结论: 本条在 Phase 5 的测试一致性审视中处理——把 scheduler test
        fixture 对齐使用 HybridQueryProperty，让 async test 真正走
        框架路径，暴露潜在的事件循环阻塞风险。暂不在 Phase 4 处理。
