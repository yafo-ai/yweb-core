5.1 scheduler fixture 迁移 —— 结论：回滚，bug 转 Phase 5B
--------------------------------------------------------

第一版尝试：
  - tests/test_scheduler/conftest.py:67  改 HybridQueryProperty 包装
  - tests/test_scheduler/integration/test_history.py:392  加 await

实测结果：
  tests\test_scheduler\integration\test_history.py
    ::test_job_execution_records_history  FAILED
    sqlalchemy.exc.PendingRollbackError:
        '生成主键失败：5次尝试后仍然冲突'
    ERROR    yweb.scheduler.history:history.py:184
        Failed to record job success:
        '_HybridTerminal' object has no attribute 'status'

根因分析：
  yweb/scheduler/scheduler.py 的 async def _execute_job() 直接调用
  同步方法 history_manager.record_start / record_success / record_failure，
  这些方法内部用 HistoryModel.query.filter(...).first()。
  Phase 4 上线 HybridQueryProperty + 测试 fixture 对齐之后：
    - .first() 在 async 上下文里返回 _HybridTerminal
    - record_start 把它当成"主键已存在" → 5 次重试 PendingRollbackError
    - record_success 走到 history.status = ... → AttributeError 被 except 吞

历史背景：
  Phase 4 前，scheduler 测试 fixture 用 raw session_scope.query_property()
  绕过保护；生产路径则挂 AsyncSafeQueryProperty → record_* 也会抛
  SynchronousOnlyOperation 被 except 吞掉。
  结论：**scheduler async executor 的历史记录功能在生产里一直是坏的**，
  Phase 4 把它从"静默失败"升级为"显性失败"。

处置（B+C 混合方案）：
  - 本轮 Phase 5：回滚 scheduler 测试 fixture 和 test_history.py 改动；
  - 在 conftest.py:67 加注释说明回滚原因 + 指向 Phase 5B；
  - Phase 5B 独立修复（run_in_threadpool 包装 3 个调用点），含回归测试；
  - 修完后 Phase 5B 同步把 scheduler fixture 改回 HybridQueryProperty。

回滚后验证：

    ...................  19 passed

本地结果:
  8 passed in 0.17s

关键实现细节:
  _leaked_session_count() 穿透 ScopedRegistry.registry 内部 dict
  观察泄漏：`registry.has()` 只看 scopefunc() 当前返回值对应的 session，
  但 HybridQuery 的 await 走 run_in_threadpool，泄漏发生在 worker 线程的
  ContextVar copy 中，主协程通过 has() 观察不到，必须走内部 dict。

L6 的 API gap 记录:
  doc 22 §7.2.3 原设计 `with db_session_scope(): await q.all()` 当前会抛
  SynchronousOnlyOperation（db_session_scope 是同步 API，get_session() 内部
  会调 check_async_safety()）。测试 L6d 以 xfail 等价的 pytest.raises 锁住这个
  现状，Phase 5B 规划修复方向：
    选项1: db_session_scope 内部自动 allow_sync()
    选项2: 新增 async_db_session_scope() 作为 async 等价入口
    选项3: 文档明确 async 脚本只允许 async_db_call + on_request_end 显式清理
